# Agent Note：桌面项目策略存储

Status: implemented

[English](2026-08-21-desktop-project-policy-storage.md) | 中文

## Problem

桌面设置此前全部是全局设置。下一产品阶段要求提供项目级执行默认值和权限边界，同时不能向客户仓库写入产品元数据，也不能保存凭据。无效项目策略必须安全关闭，不能静默授予宽松默认值。

## Decision

桌面应用把已配置策略存储在 `$DSH_HOME/desktop-project-policies.json`，以规范化的绝对项目根目录为键。版本化文件通过共享的 `writeFileAtomic` 工具写入；该工具使用独占创建的随机同目录临时文件和原子重命名。文件缺失表示没有项目覆盖；文件无效时先按时间戳保留损坏副本，再替换为空存储。

每项策略校验封闭的桌面执行预设、可选且有长度限制的 provider 与模型标识、子代理权限上限、联网策略、无凭据代理覆盖、交叉审核默认值及绝对读写根目录。项目根目录必须可读；每个写入根目录必须位于某个读取根目录中；含用户信息的手动代理 URL 会被拒绝。

收窄后的设置 preload API 允许渲染器选择目录、加载安全草稿或已配置策略、保存经过校验的策略，以及停用项目覆盖。目录选择与存储由主进程持有。任何超过只读权限、明确允许联网或含写入根目录的策略，都必须携带单独的确认标记，并在 IPC 边界再次强制校验。

主窗口 preload 还只暴露按绝对项目根目录解析策略的能力。Connection 客户端持有原生载体细节，并发布与传输方式无关的 `resolveProjectPolicy` 服务方法；Agent 预设界面消费已声明的 Connection 服务，不直接读取 Electron 全局对象。策略只对空白会话生效。会话级显式选择始终优先，包括策略查询尚未返回时已经应用的选择。禁止联网解析为纯本地预设；交叉审核解析为固定的 Codex→Claude 审核预设。

## Alternatives considered

**向每个仓库写入策略文件。** 未采用，因为仅打开桌面设置不应修改客户仓库，而且团队可能不希望把本地产品策略提交到版本控制。

**为每个打开的项目隐式创建宽松策略。** 未采用，因为缺少配置时应保留现有全局行为，配置损坏时必须安全关闭。

**保存任意 provider 模块或命令。** 未采用，因为渲染器边界必须保持为封闭产品配置，不能成为代码加载机制。

## Consequences

存储、校验、设置界面和默认执行方式解析现在可以独立测试，并且不含凭据。权限上限、项目代理覆盖和读写根目录仍是策略草稿，只有 Host 执行层与沙箱层消费后才能生效；应用目前不能宣称这些字段已经受到运行时强制约束。
