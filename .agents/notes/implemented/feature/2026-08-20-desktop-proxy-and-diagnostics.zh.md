# Agent Note: 桌面端代理控制与可操作诊断

Status: implemented

[English](2026-08-20-desktop-proxy-and-diagnostics.md) | 中文

## Problem

打包后的桌面应用只在启动时继承一次 macOS 代理，并直接显示子进程原始错误。用户无法主动选择直连或手动代理，无法在不重启的情况下感知系统代理变化，无法区分网络可达性与认证问题，也无法在 Codex 或 Claude Code 失败时安全复制有用的诊断报告。

## Decision

桌面壳在 `DSH_HOME` 下持久化一份小型代理设置。它支持系统、手动和直连三种模式，把所选模式投影为常见的大小写子进程环境变量，始终绕过回环地址和 `.local` 目标，并在系统模式下轮询 macOS 系统代理。帮助菜单显示不含凭据的实际生效地址，立即应用模式变更，并对 OpenAI、Anthropic、DeepSeek 和 Ollama 执行不携带凭据的可达性测试。

Codex 和 Claude Code 的启动边界使用固定安全类别标记已识别的认证、超时、网络、包缺失和 Node 包装器错误，未识别的细节仍使用 `unknown`。桌面诊断把这些类别翻译为原因和建议操作。文件导出与剪贴板复制共用一个有长度限制的报告生成器。脱敏在日志落盘前执行，并在生成报告时再次执行，覆盖常见凭据、OAuth 查询参数和邮箱地址。报告不会枚举进程环境，也不会自行通过网络发送。

## Alternatives considered

**只依赖 macOS 系统设置。** 这种方式不需要产品设置，但无法支持直连模式、应用级手动代理、实际状态展示，也无法在用户切换网络后稳定排错。

**使用携带认证的 API 请求测试连接。** 这样能区分账号有效性，但需要读取凭据，并可能产生费用或泄露密钥。可达性测试把任意 HTTP 响应视为网络成功，认证状态继续由各 provider 的专用状态检测负责。

**把 provider 原始错误作为主要界面。** 原始信息在脱敏报告中仍有价值，但单独展示时难以指导用户处理已知问题，也可能包含授权材料。因此界面优先显示分类后的说明，未知错误只保留经过长度限制的安全摘要。

## Consequences

用户无需重启应用或打开终端即可修改并验证桌面网络，同时 Ollama 和其他回环服务保持直连。支持报告更容易共享，默认安全性也更高。正式桌面设置页可直接输入手动代理地址，并复用同一套经过校验的偏好存储和环境变量投影函数。可达性测试只证明传输可用，不证明订阅状态或 API 授权有效。
