# Agent Note：桌面本机工具证据约束

Status: implemented

[English](2026-08-22-desktop-local-tool-grounding.md) | 中文

## 问题

桌面本地 Qwen 路由可能已经成功执行 `bash` 和文件系统工具，却随后声称自己无法检查用户机器或运行软件。权限选择器实际上正常工作；矛盾内容是在工具成功后由模型生成的。内置预设原先只在文件不存在时复制，因此应用升级后，已经安装的提示仍然会停留在旧版本。

## 决策

桌面组合在 `repeat-tool-reminder` 中为 shell 和文件系统工具启用可选的成功证据约束。每轮用户请求里首个匹配工具成功后，系统会增加一条有日志记录的插件上下文，说明结果来自真实本机运行环境，必须作为直接证据使用，不能再被通用能力免责声明否定。失败和被拒绝的调用不会生成成功证据上下文。该机制只提供行为约束，不授予任何权限。

本地模式和自动模式的桌面 persona 现在明确区分权限策略与模型能力：Full access 会授权当前工具可提供的最广操作范围；环境事实必须先通过工具检查；成功结果属于直接观察；失败必须精确报告。

桌面预设安装器只迁移摘要与已知历史内置版本一致的文件。未知内容始终视为用户所有且绝不覆盖。因此，未修改的旧版本地和自动预设会升级，自定义预设仍会保留。

## 备选方案

**只依赖 persona 文本。** 没有采用，因为对较小的本地模型约束太弱。已观察到的矛盾就发生在有效工具调用之后，此时紧随结果注入提醒能提供更强的证据约束。

**把 Full access 当成修复。** 没有采用，因为工具本来就已经成功执行。扩大权限无法修复回答生成时的矛盾，只会在不解决根因的情况下削弱安全性。

**覆盖所有已安装预设。** 没有采用，因为复制出来的预设属于可编辑用户文件。按摘要迁移能够更新已知内置版本，同时不破坏自定义内容。

## 影响

桌面本机工具每轮首次成功会增加一条较短的模型可见上下文。消息会持久化并在会话日志中保留来源，但会消耗少量 token。未配置 `evidenceInclude` 时，原有重复循环检测行为完全不变。以后修改内置提示模板前，需要先登记上一版本摘要，才能继续安全迁移。

## 验证

- 真实会话日志显示 `ls`、`which python3` 和 `python3 --version` 都已成功，证明问题不是权限拒绝。
- Guard 测试覆盖每轮一次证据提醒，以及工具失败时不产生提醒。
- 桌面安装器测试覆盖已知托管版本迁移与用户修改保留。
- 桌面组合验证会确认安装后的提示和证据约束插件配置已经生效。
