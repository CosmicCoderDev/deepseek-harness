# Agent Note: 桌面端直接 Provider 执行

Status: proposed

[English](2026-08-21-desktop-direct-provider-execution.md) | 中文

## Problem

桌面端的“Codex 直接模式”和“Claude Code 直接模式”仍由所选本地模型运行第一层 Agent，再依赖提示词要求该模型调用 `subagent_codex` 或 `subagent_claude_code`。这条链路会受到本地模型工具选择能力、上下文长度和模态能力限制。模型可能跳过或编造工具；图片会在不支持视觉的 Qwen 处提前被拒绝；Provider 失败后模型还可能生成未经验证的替代答案。因此，当前“直接”只表示强委派提示，不是真正的执行路由。

桌面原生 Host 已禁用需要 `DEEPSEEK_API_KEY` 的 `web_search`，但源码 Web Host、旧安装包、旧 Host 和已创建会话仍可能保留不同的工具快照。内置预设使用只在文件不存在时复制的策略，已安装的旧模板也不会随应用版本升级。这会让界面与实际执行能力不一致。

## Proposal

把“谁执行任务”提升为 Host 持有的结构化会话属性，并为 Codex 与 Claude Code 建立不经过本地模型的直接执行通道。提示词仍用于普通 Agent 行为，但不再承担 Provider 路由、安全限制或失败判断。

### 执行模式与界面

新会话在创建时固定一个 `executionTarget`：`local-model`、`codex`、`claude-code` 或 `orchestrated`。模型选择器显示两类选项：本地／API 模型和外部执行者。选择 Codex 或 Claude Code 后，输入直接进入对应 Provider；Qwen 不参与解析、改写、工具选择或总结。`orchestrated` 才允许本地模型调用多个 Provider 或固定工作流。运行中的会话不能静默切换执行目标；切换必须新建会话或走显式迁移操作。

界面必须同时显示执行目标和实际模型信息，避免把 Provider 名称伪装成本地模型。Provider 未安装、未登录、网络不可用或不支持当前输入时，发送前给出明确原因；失败后不得自动回退到 Qwen 或另一个 Provider。

### Host 与协议

在 Host 增加独立的外部执行能力注册表，例如 `ExternalExecutorRuntime`，按稳定名称注册 `codex` 和 `claude-code`。它接收规范化工作目录、内容块、权限上限、代理环境、取消信号和诊断接收器，返回统一的流式事件与终态。该能力不要求父 `Agent`，也不伪造子代理父子关系。

现有 Codex/Claude Code 包把进程启动、认证、协议交互和错误分类下沉为可复用执行器；`SubagentProvider` 只作为适配器调用该执行器并补充父子会话语义。直接会话和子代理因此共享同一套官方 CLI、权限映射、项目代理、终止逻辑与错误分类，不复制两套实现。

会话创建协议加入封闭的 `executionTarget` 字段并持久化到不可变 `SessionHeader`。`session.prompt` 由 Host 按该字段分派：普通目标进入现有 Agent inbox；外部目标进入直接执行控制器。渲染器不能提交可执行文件路径、命令行、环境变量或 Provider 模块。恢复会话时使用持久化目标，不能根据当前界面选择重新推断。

### 会话记录与并发

直接执行仍使用标准 Session 日志保存用户输入、Provider 输出、取消、失败和模型／Provider 来源，但不伪造本地模型步骤或工具调用。Host 为每个直接会话维护单一活动运行；`queue`、取消、重试、恢复和“会话忙”规则与普通会话保持可预测的一致语义。Provider 输出通过现有事件流增量发送，最终文本只记录一次。

直接执行失败必须形成结构化终态，包括 `not-installed`、`not-authenticated`、`network`、`proxy`、`permission-denied`、`unsupported-input`、`timeout`、`cancelled` 和 `unknown`。错误终态可以重试，但不能追加一段本地模型生成的“看似成功”答案。

### 图片和附件

执行器注册时声明 `text`、`image` 和文件附件能力。输入控件依据当前执行目标的能力决定是否允许发送，而不是依据 Qwen 的能力。第一阶段只开放已被官方协议和自动化测试证明可传输的内容类型；若 Codex 或 Claude Code 适配器仍只支持文本，界面应显示“当前直接执行器仅支持文本”，不能先交给 Qwen，也不能把图片静默转成未知内容。

图片支持需要在 Provider 适配层实现明确的内容映射、大小和类型限制、临时文件生命周期、项目读权限检查及日志脱敏。只有真实端到端测试证明目标 CLI 收到并使用图片后，才把对应能力标记为可用。

### 搜索工具与预设升级

桌面 Host 在组合完成后继续验证 `web_search` 不存在。产品还应显示当前载体是“桌面 Host”还是“Web Host”，防止用户把源码 Web 页面误认为桌面运行环境。没有有效搜索 Provider 凭据时，Web Host 也应默认不向模型注册必然失败的搜索工具；显式启用在线搜索时再注册并显示 Provider 状态。

内置预设改为版本化托管资源。应用记录模板版本和内容摘要，只覆盖仍等于旧版内置摘要的文件；用户修改过的预设保留并标记为自定义。升级后删除把 `codex-direct`、`claude-direct` 描述为提示词委派的旧模板，改由结构化 `executionTarget` 提供直接模式。旧会话继续按原有不可变配置恢复，新会话使用新定义。

### 交付阶段

第一阶段建立执行器注册表、会话字段和纯文本 Codex 直连；第二阶段接入 Claude Code、流式输出、取消和结构化错误；第三阶段完成版本化预设迁移和 Web Search 凭据门禁；第四阶段按官方协议分别启用经过验证的图片与附件能力；第五阶段对安装后的应用执行本地 Qwen、Codex、Claude Code、代理、离线、认证过期、恢复和失败不回退验收。

## Alternatives considered

**继续加强直接模式提示词。** 不采用，因为提示词不能保证工具调用，也不能绕过本地模型的图片、上下文和工具能力检查。

**在 `session.prompt` 中构造一个假的父 Agent 再调用现有子代理。** 不采用，因为伪造父子关系会污染会话树、权限来源、生命周期和诊断，并让直接执行错误地依赖 Agent loop。

**把 Codex 和 Claude Code 包装成普通 LLM adapter。** 不作为首选，因为两者是带工作区、工具和权限语义的 Agent 执行器，不是只完成一次无状态模型补全的 LLM。可以在界面与模型并列显示，但 Host 内部保持独立能力边界。

**失败时自动回退本地模型。** 不采用，因为用户选择直接 Provider 是明确的执行与信任决定；静默回退会产生来源错误和未经验证的结果。

## Acceptance criteria

- 选择 Codex 或 Claude Code 后，即使 Ollama 停止或 Qwen 不可用，纯文本任务仍能执行；日志中不存在本地模型调用或 `subagent_*` 工具调用。
- 直接会话的执行目标被持久化并在恢复后保持不变；渲染器无法借该字段注入命令、模块或环境变量。
- Provider 不可用、登录过期、代理失败、取消和超时均产生稳定错误，不触发本地模型或其他 Provider 回退。
- 输入控件只允许当前执行器声明且经过端到端验证的模态；不支持的图片在发送前被准确拒绝。
- 桌面 Host 的工具目录不包含 `web_search`；无搜索凭据的默认 Web Host 不暴露必然失败的搜索工具。
- 升级测试证明未修改的旧内置预设会迁移，用户修改过的预设不会被覆盖，旧会话仍可恢复。
- 安装后的 macOS 应用完成 Codex、Claude Code、本地模型和组合工作流的独立验收，且每条结果明确标注真实执行来源。

## Risks

直接会话绕过普通 Agent loop 后，需要明确复用会话日志、排队、取消和恢复语义，否则会形成第二套不兼容的会话系统。Codex 与 Claude Code 官方协议的附件能力可能变化，能力声明必须保守并由适配器测试固定。版本化预设迁移若缺少旧内容摘要，可能无法可靠区分内置文件和用户修改，因此首个迁移版本需要保留备份并允许人工恢复。把外部执行者放进模型选择区域可能令用户误解其计费和权限，界面必须持续显示 Provider、账号状态、权限档位和代理模式。
