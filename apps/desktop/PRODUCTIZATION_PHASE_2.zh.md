# DeepSeek Harness 桌面版产品化第二阶段

本文定义桌面版在完成代理管理和基础错误诊断之后的下一阶段开发范围。目标是让非开发人员可以完成配置、选择权限、验证子代理并稳定运行打包应用，而不要求使用终端或记忆内部工具名称。

## 范围与顺序

| 阶段 | 工作项 | 交付结果 |
| --- | --- | --- |
| A | 正式桌面设置页 | 在一个桌面原生设置窗口中管理子代理、代理、权限和诊断 |
| B | 子代理权限三档 | 把 Codex 与 Claude Code 原生参数映射为只读分析、项目开发、完全访问 |
| C | 桌面端端到端测试 | 从打包应用验证设置持久化、代理、权限、Codex 与 Claude Code 调用 |
| D | ASAR 调研与启用 | 在动态插件、原生模块和两个 CLI 均可运行的前提下启用 ASAR |

Apple Developer ID 签名、公证和可信自动更新不属于本阶段。它们继续等待开发者资质。

## A. 正式桌面设置页

### 页面结构

桌面应用新增“设置 → 桌面功能”入口，打开独立的受限 Electron 设置窗口。页面包含四个区域：

1. **子代理**：显示 Codex、Claude Code 的内置状态、登录状态、网络状态、版本、最近一次测试结果，并提供刷新、测试和登录指引。
2. **代理**：使用单选项选择自动读取系统代理、手动代理或不使用代理；手动模式提供真实地址输入框，不再依赖剪贴板；显示当前生效地址和本地绕过规则。
3. **权限**：选择只读分析、项目开发或完全访问；展示两个 provider 对应的实际原生模式和风险说明。
4. **诊断**：执行四服务连通性测试，复制脱敏报告，打开日志目录或导出诊断文件。

### 安全边界

- 设置页保持 `nodeIntegration: false`、`contextIsolation: true` 和沙箱开启。
- preload 只暴露设置快照、保存、测试、复制诊断和打开日志这组固定操作。
- 主进程验证所有模式和 URL，不接受任意文件路径、命令或网络目标。
- 设置文件使用 `0600` 权限写入 `$DSH_HOME`；代理凭据不得出现在页面摘要或诊断中。

## B. 子代理权限三档

| 用户模式 | Codex | Claude Code | 用途 |
| --- | --- | --- | --- |
| 只读分析 | `never` | `plan` | 阅读、分析和方案输出，不允许写入项目 |
| 项目开发 | `approve-for-me` | `acceptEdits` | 允许工作区内开发，危险操作继续受原生沙箱与拒绝策略约束 |
| 完全访问 | `dangerously-bypass-approvals-and-sandbox` | `bypassPermissions` | 仅在用户明确确认后启用，适合受控环境中的完整自动化 |

权限选择持久化在桌面设置中，并在下一次 Host 启动时投影为两个 provider 的固定配置。完全访问必须经过二次确认。设置页明确提示“保存后重启桌面 Host 生效”，本阶段不在运行中的子代理调用中途切换权限。

## C. 端到端测试

### 无凭据测试

- 打包应用能在空 `DSH_HOME` 下启动。
- 设置页能读取、修改并重新读取代理与权限。
- 非法代理 URL、非法权限值和未确认的完全访问均被拒绝。
- 自动代理刷新后快照更新；本地地址始终绕过代理。
- 诊断复制不会包含 API Key、OAuth 参数、邮箱或代理密码。
- ASAR 构建不得依赖源码仓库中的软链接或外部 Node.js。

### 真实产品测试

- 已登录环境中 Codex 完成一次只读目录检查。
- 已登录环境中 Claude Code 完成一次只读目录检查。
- 未登录、网络关闭和代理错误分别产生可理解的固定类别。
- 真实产品测试在缺少登录状态时明确跳过，不把跳过记录为通过。

## D. ASAR 启用门槛

当前应用关闭 ASAR，是因为 profile loader 的动态插件、原生模块、Codex 包装器和 Claude Code 平台二进制需要真实路径。不能只修改 electron-builder 开关。

实施步骤：

1. 盘点运行时必须由子进程或原生加载器直接访问的文件。
2. 主 JavaScript 与静态配置进入 `app.asar`。
3. Codex、Claude Code、`node-pty`、原生模块、动态 profile 依赖及必须建立软链接的目录进入 `app.asar.unpacked`。
4. profile loader 使用 `process.resourcesPath` 解析解包后的插件根目录，不把 ASAR 内部路径作为软链接目标。
5. 只有在隔离打包冒烟、设置页测试、Codex 真实调用和 Claude Code 真实调用全部通过后，才保留 `asar: true`；否则保持关闭并记录具体阻塞项。

## 数据文件

桌面偏好统一保存为 `$DSH_HOME/desktop-settings.json`，版本从 `1` 开始：

```json
{
  "version": 1,
  "proxy": {
    "mode": "system"
  },
  "subagentPermission": "read-only"
}
```

旧的 `$DSH_HOME/desktop-proxy.json` 在首次读取时迁移到新文件。迁移成功前不删除旧文件；新设置写入采用原子替换，避免异常退出留下半个 JSON 文件。

## 验收标准

- 用户能在可见设置页完成代理、权限、状态检测和诊断操作。
- 手动代理具有实际输入框，保存后立即影响新建的 provider 子进程。
- 完全访问未经二次确认无法保存。
- 重启后权限映射与页面显示一致。
- 两个真实子代理测试和打包冒烟测试均通过。
- ASAR 只有在全部运行时依赖验证通过后启用，不以安装包能打开作为唯一成功标准。

## 当前实施结果

阶段 A、B 和无凭据的阶段 C 已完成实现。打包冒烟测试会实际打开设置页，通过受限 IPC 保存并回读代理与权限，然后确认主界面插件完成挂载。真实产品测试继续使用已登录机器上的 Codex 和 Claude Code provider 测试；缺少登录状态时不得记为通过。

阶段 D 已执行两轮打包验证，但暂不启用。第一轮只解包 Codex、Claude Code 与原生模块；第二轮解包完整 `node_modules`。两轮都能启动主进程和 Host，但 `dsh-plugin://` 的 parser preload 在 `app.asar` 路径组合下未注册 `@deepseek-ai/dsh-client-modules/client.js`，扩展后的冒烟测试因此正确失败。当前构建继续使用 `asar: false`，直到自定义协议的插件物理路径和 preload 执行顺序具备单独回归覆盖。
