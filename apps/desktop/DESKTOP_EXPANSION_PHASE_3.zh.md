# DeepSeek Harness 桌面版第三阶段扩展计划

本文定义桌面版在完成正式设置页、代理管理、权限三档、Codex／Claude Code 登录引导与真实产品验证之后的下一阶段工作。目标不是继续堆叠模型或提示词，而是把“选择谁执行、如何授权、如何组合、如何证明结果”变成普通用户可理解、运行时可约束、测试可验证的产品能力。

## 一、当前基线

截至 `feat/electron-desktop-rc8` 分支提交 `cf95494bc3`，已经完成：

- Apple Silicon 未签名桌面测试包、DMG 与 ZIP。
- Electron 主进程内置 Harness Host，不依赖单独启动 Web 服务。
- 本地 Ollama 与 `qwen3-coder:30b` 配置引导。
- Codex、Claude Code 内置、状态检查、登录／重新登录入口。
- 自动读取 macOS 系统代理、手动代理、直连和四服务连通性测试。
- 只读分析、项目开发、完全访问三档子代理权限。
- 完全访问二次确认、受限 IPC、诊断脱敏和日志导出。
- 安装包主界面／设置页冒烟测试。
- Codex、Claude Code 安装包内真实只读调用验证。

Apple 签名、公证、可信自动更新仍等待 Apple Developer 资质。ASAR 仍受 parser preload 兼容问题阻塞。Intel Mac 尚无构建和实机验证。

## 二、第三阶段原则

1. **产品选择代替提示词猜测**：用户在界面中选择本地模型、Codex、Claude Code 或组合工作流，不要求本地模型记住内部工具名。
2. **运行时策略代替模型自律**：provider、权限、降级和联网边界由 Host 执行，提示词只负责解释行为。
3. **失败不能伪装成成功**：指定 provider 失败时必须显示失败；没有用户授权不得自动换用其他 provider。
4. **先修稳定性，再扩展能力**：状态检测、配置保护和 Host 重启机制是任务级路由的前置条件。
5. **扩展采用注册机制**：新增 provider 不应反复修改设置页、IPC 和主进程分支判断。
6. **每次执行可追溯**：用户可以确认任务由谁执行、使用何种权限、是否联网、是否经过复核。

## 四、阶段 E：稳定性前置修复

### E1. 子代理状态服务

当前设置页可见时每五秒调用状态接口，而状态接口会启动 Codex 与 Claude CLI。单次检测最长十秒，存在重复检测和进程叠加风险。

改为主进程状态服务：

- 同一 provider 同时最多一个检测任务。
- 保存最后成功状态、检查时间、检查中状态和最后错误。
- 设置页通过事件订阅获得变化，不直接循环启动 CLI。
- 登录完成、代理切换、用户点击刷新时触发检查。
- 后台自动检查间隔不短于三十秒。
- 设置窗口关闭后停止非必要刷新。

### E2. 损坏设置保护

`desktop-settings.json` 只有在文件不存在时才能创建默认值。解析失败、版本不支持或字段非法时：

- 不覆盖原文件。
- 原文件移动为 `desktop-settings.corrupt-<timestamp>.json`。
- 使用只读分析和系统代理作为安全默认值。
- 设置页显示恢复提示。
- 诊断日志记录固定错误类别，不记录代理凭据。

### E3. 安全重启 Host

权限保存后提供“立即重启 Host”和“稍后”选项：

1. 停止接收新任务。
2. 检查是否存在运行中的请求或子代理。
3. 用户确认后取消或等待当前任务。
4. 释放旧 Host、IPC 请求与子进程。
5. 使用新权限和代理重新启动 Host。
6. 重新加载主界面，但不退出桌面应用。
7. 失败时恢复到安全只读配置并显示可操作错误。

## 五、阶段 F：任务级执行方式选择

### F1. 用户界面

在消息输入区模型选择旁增加“执行方式”：

| 选项 | 含义 |
| --- | --- |
| 自动选择 | 根据任务类型和 provider 状态选择执行者 |
| 本地模型 | 全程使用当前本地模型，不调用云端子代理 |
| Codex | 直接由 Codex 执行，失败时不自动降级 |
| Claude Code | 直接由 Claude Code 执行，失败时不自动降级 |
| Codex + Claude 审查 | Codex 产生结果，Claude Code 独立审核 |

选择必须作为结构化会话／任务配置传给 Host，不能只拼接到用户提示词。任务顶部持续显示当前执行方式。

### F2. 自动选择规则

第一版使用可预测的显式规则，不使用另一个付费模型做路由：

- 日常问答、已有资料总结、低风险文本处理：本地模型。
- 仓库检查、代码实现、测试修复：Codex。
- 方案评审、文档分析、独立复核：Claude Code。
- 用户标记高风险或要求交叉验证：Codex + Claude 审查。
- provider 未登录、网络失败或权限不足：停止并向用户说明，不静默降级。
- 用户可在发送前查看自动选择结果并改选。

### F3. 权限关系

- 任务权限不得高于桌面设置中的全局上限。
- 本地模型与子代理分别显示其工具权限。
- “完全访问”仍要求桌面级二次确认，任务选择不能绕过。
- 组合工作流中每个阶段继承同一上限，但可以进一步收窄。

## 六、阶段 G：Provider 注册接口

桌面层定义统一 provider 描述，避免继续硬编码 Codex 和 Claude：

```ts
interface DesktopSubagentProvider {
  readonly id: string
  readonly displayName: string
  readonly capabilities: readonly string[]
  readonly supportedPlatforms: readonly string[]
  inspect(): Promise<ProviderStatus>
  login(): Promise<void>
  smokeTest(): Promise<ProviderTestResult>
  permissionMode(tier: PermissionTier): string
}
```

安全要求：

- Provider ID 来自封闭注册表，不接受渲染器传入模块路径。
- 登录命令、可执行文件和参数由 provider 实现固定生成。
- 状态和错误只返回结构化、脱敏字段。
- 设置页通过 provider 列表自动渲染。
- provider 声明是否支持只读、工作区修改、结构化输出、继续会话和工具限制。

第一轮只迁移 Codex、Claude Code，行为不得变化。后续可评估 Gemini CLI、ACP provider、企业内部代理或其他兼容实现。

## 七、阶段 H：多代理工作流

### H1. 首个工作流

首个正式模板为“Codex 开发 → Claude 审核”：

1. Codex 读取任务和工作区，完成实现或分析。
2. 固化 Codex 输出、改动摘要和验证结果。
3. Claude Code 获得原始需求、Codex 结果和允许读取的工作区。
4. Claude 输出通过、需修改或阻塞，并给出证据。
5. 若需修改，默认回到用户确认，不自动无限循环。

### H2. 后续模板

- Claude 出方案 → Codex 实现。
- Codex 与 Claude 独立分析 → 本地模型汇总。
- 本地模型拆分任务 → 云端 provider 处理指定难点。
- 仅本地模型与本地工具，禁止联网。

### H3. 共同约束

- 每个阶段显示执行者、权限、联网状态和结果。
- 每个阶段单独记录成功、失败、跳过和取消。
- provider 失败不得由本地模型编造替代结果。
- 默认最多一次实现和一次审核；增加循环必须由用户确认。

## 八、阶段 I：项目配置档案

配置优先级：单次任务覆盖项目配置，项目配置覆盖全局设置。

项目配置至少包含：

- 默认执行方式。
- 默认 provider／模型。
- 权限上限。
- 是否允许联网。
- 代理模式覆盖。
- 是否默认启用交叉审查。
- 允许读取和写入的工作区边界。

项目配置只保存产品策略，不保存 OAuth 授权码、API Key 或代理密码。

## 九、阶段 J：执行与成本面板

每次任务记录并展示：

- 实际 provider 和模型。
- 本地或云端。
- 开始时间、耗时和最终状态。
- 输入、输出、缓存和推理 Token（provider 能提供时）。
- 估算费用（仅在定价来源明确且用户启用时）。
- 权限档位、是否使用工具、是否修改文件。
- 是否经过第二 provider 审核。
- 失败阶段和脱敏诊断编号。

没有 provider 证据的字段显示“未知”，不得估算成精确值。

## 十、阶段 K：能力管理页面

在 provider 注册机制稳定后，统一展示：

- 子代理 provider。
- MCP 服务。
- Skills。
- 本地与远程模型。
- 工具与权限。

支持启用／禁用、来源说明、连接测试、权限查看和兼容性诊断。第三方插件安装和市场功能不进入首版；先保证来源与权限可审计。

## 十一、测试策略

### 单元与契约测试

- 路由规则对相同输入给出稳定结果。
- 用户指定 provider 时不得调用其他 provider。
- 自动模式失败不会静默降级。
- 任务权限不会超过全局权限上限。
- Provider 注册拒绝重复 ID、未知能力和渲染器路径输入。
- 损坏设置会保留原文件并回退安全默认值。
- 状态检查不会并发重入。

### 安装包测试

- 输入区可以选择五种执行方式并在重启后保持预期状态。
- 设置页状态刷新不持续产生重复 CLI 进程。
- Host 重启后权限映射生效，主窗口不退出。
- Codex 和 Claude Code 真实调用继续返回固定标记。
- 双代理工作流能区分实现失败与审核失败。
- 未登录产品必须显示 `SKIP` 或阻塞，不能显示通过。

## 十二、验收标准

- 用户无需写专用提示词即可明确选择 Codex 或 Claude Code。
- 自动模式在发送前显示将使用的执行者。
- 指定 provider 失败时不会自动换模型或伪装成功。
- 权限、联网和工作区边界在任务开始前可见。
- Codex → Claude 审核工作流具备清晰阶段状态和停止条件。
- Provider 注册后，设置页与测试脚本不再包含 Codex／Claude 专属分支扩散。
- 状态检测、损坏配置和 Host 重启均有安装包级回归验证。

## 十五、实施状态

批次 1 已于 2026-08-20 完成实现：

- 子代理状态检查由主进程缓存，重复刷新共享同一进行中任务；后台周期改为三十秒，设置页通过事件接收变化，不再每五秒直接启动两个 CLI。
- `desktop-settings.json` 缺失时继续迁移旧代理配置；文件存在但内容损坏、版本不支持或字段非法时，先保留为带时间戳的 `desktop-settings.corrupt-*.json`，再写入系统代理与只读权限的安全默认值。
- 权限变化后设置页显示“立即重启 Host”；存在活动请求时拒绝重启，无活动请求时释放并重新创建 Host、重新加载主界面。重启失败会尝试恢复只读权限和安全 Host。
- 安装包冒烟测试会注入损坏设置，验证备份与恢复提示，然后修改权限、重启真实 Host 并确认新配置生效。

批次 2 已于 2026-08-20 完成首轮实现：

- 桌面端新增“本地模型”和“自动选择执行者”两个结构化会话预设，并继续提供 Codex 直接模式、Claude Code 直接模式和 Codex + Claude 预览入口；用户不需要在消息中编写内部工具名。
- 本地模式从工具目录中移除 Codex／Claude Code，形成运行时能力边界；直接模式固定唯一云端执行者，失败必须原样报告，不允许本地模型伪装成功。
- 自动模式采用固定规则：普通问答与低风险文本留在本地，仓库实现与调试选择 Codex，评审与文档分析选择 Claude Code；显式用户选择优先，provider 不可用时停止且不静默降级。
- 现有 Host 规定运行过一次的会话不能切换 Agent 组装，因此首版选择作用于即将开始的新会话，并在会话顶部持续显示。真正的单一会话逐任务热切换需要新的 Host 任务路由协议，不能通过偷偷修改提示词绕过该安全边界。
- “Codex + Claude”本批只作为双工具预览；自动的 Codex 开发 → Claude 审核仍属于批次 4，避免把尚未实现的工作流标成可用。

批次 3 已于 2026-08-21 完成实现：

- 新增封闭的桌面子代理 Provider 注册表，统一描述 ID、显示名称、能力、支持平台、连通性地址、状态检测、登录命令和权限档位映射。
- Codex 与 Claude Code 的状态检测、内置可执行文件解析、登录启动、权限环境变量及连接测试均迁移到各自 Provider 描述中；主进程不再用分支分别组装这些行为。
- 设置页通过注册表投影的 `providers` 列表动态生成状态与登录卡片，同时暂时保留旧的 `codex`／`claude` 状态字段作为兼容层。
- 注册表拒绝重复 ID 和未声明能力，渲染器只能提交封闭 Provider ID，不能传入模块路径、可执行文件或命令参数。
- 单元测试覆盖注册顺序、重复 ID、未知能力和原生权限映射；安装包冒烟测试验证注册表投影进入设置 IPC。

批次 4 已于 2026-08-21 完成实现：

- 新增正式的“Codex 开发 → Claude 审核”桌面预设，以单一 `codex_claude_review` 工具承载完整任务，不要求本地模型记忆 provider 工具名。
- provider 顺序由工具代码固定为 Codex 后 Claude Code，而非依赖提示词；该预设从模型工具目录中移除两个独立 provider 工具，防止绕过固定流程。
- Codex 完成实现或分析并返回验证证据后，Claude Code 获得原始需求、Codex 输出和共享工作区，只执行独立审核，不修改文件。
- Codex 启动／执行失败与 Claude Code 审核失败分别报告；Codex 失败时不会启动 Claude Code。
- Claude 审核必须返回 `PASS`、`NEEDS_CHANGES` 或 `BLOCKED`。后两者以及无有效结论均停止等待用户决定，不自动发起修复循环。
- 单元测试覆盖 provider 固定顺序、结果传递、结论映射、资源释放及 Codex 失败短路；桌面预设测试验证两个独立 provider 工具被结构性禁用。

下一批次为阶段 I、J：项目级策略与可观测性。Apple 签名、公证和自动更新仍按已确认范围暂缓。

批次 5A 已于 2026-08-21 开始实施：

- 新增《桌面版项目策略与可观测性实施方案》，明确项目覆盖优先级、最小权限语义、任务记录证据来源、脱敏要求和分批验收标准。
- 新增版本化项目策略 schema 与 `$DSH_HOME/desktop-project-policies.json` 私有原子存储；未配置项目保持现有行为。
- 项目策略校验覆盖固定执行方式、provider／模型标识、权限上限、联网、无凭据代理覆盖、交叉审核及读写根目录；写入边界必须位于读取边界内。
- 损坏或版本不支持的项目策略文件会先保留，再回到“停用全部项目覆盖”，不会启用宽松默认值。
- 设置页已经通过收窄 preload API 支持选择项目、加载安全草稿、保存或停用覆盖；目录选择和存储由主进程持有，权限、联网或写入范围扩大必须在 IPC 边界二次确认。
- 项目默认执行方式已接入空白新会话边界：主进程按会话项目目录解析已配置策略，显式任务选择优先；禁止联网强制进入本地模式，交叉审核强制进入正式 Codex → Claude 工作流。未配置项目不改变原有行为，运行中的会话不会被热切换。
- 当前接入只覆盖执行方式和“禁止联网时不得选择云端 provider”这一结构性边界。权限上限、项目代理及读写根目录仍显示为策略草稿，不得宣称已在任务沙箱中生效。
- 下一步是把权限上限、项目代理和读写目录接入真实 Host 执行边界，然后实现任务／阶段记录及执行详情面板。
