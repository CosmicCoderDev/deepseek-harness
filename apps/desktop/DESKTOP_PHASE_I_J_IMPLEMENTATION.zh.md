# DeepSeek Harness 桌面版项目策略与可观测性实施方案

本文细化第三阶段计划中的阶段 I（项目配置档案）与阶段 J（执行与成本面板）。实施原则是先建立可验证的数据与执行边界，再增加界面；没有 provider 证据的数据必须显示“未知”，不得由本地模型推断。

## 一、当前基础

- 全局桌面设置已经具备代理模式、子代理权限档位、损坏文件恢复与 Host 安全重启。
- 会话开始前已经可以选择本地、自动、Codex、Claude Code、双工具预览以及固定交叉审核模式。
- Codex 与 Claude Code 已由封闭 Provider 注册表管理。
- 固定审核工具可以区分 Codex 实现失败与 Claude Code 审核失败，并阻止自动修复循环。
- 当前缺少项目级覆盖、任务级执行记录、统一诊断编号和面向用户的历史面板。

## 二、项目配置档案

项目策略保存在 `$DSH_HOME/desktop-project-policies.json`，而不是写入客户仓库。文件权限为当前用户可读写，采用临时文件加原子替换。策略以规范化的绝对项目根目录为键，不保存 OAuth 授权码、API Key、Cookie、代理用户名或代理密码。

每个已配置项目包含：

- 默认执行方式：本地、自动、Codex、Claude Code、双工具预览或固定交叉审核。
- 可选的默认 provider 与模型 ID；它们只是封闭 ID，不是模块路径或命令行。
- 权限上限：只读分析、项目开发或完全访问。
- 联网策略：继承全局、允许或禁止。
- 代理覆盖：继承全局、系统代理、手动代理或直连；手动地址不得含凭据。
- 是否默认启用交叉审核。
- 允许读取和写入的绝对目录；写入目录必须同时位于读取目录范围内。

优先级固定为：单次任务明确选择 > 项目配置 > 全局桌面设置。权限采用上限语义，低层配置不能扩大高层允许范围。未配置项目时不生成隐式策略，也不改变现有行为。

## 三、执行时约束

Host 启动或项目切换时解析当前项目策略，并生成只读的有效策略快照。模型只能看到最终允许的执行方式和边界，不能提交 provider 模块、可执行文件或任意代理命令。任务开始后快照固定；策略变化只影响下一项任务，避免运行中权限漂移。

若策略禁止联网，则云端 provider 和网络工具在工具目录中不可见。若权限上限为只读，即使全局设置为完全访问，provider 仍使用只读原生权限。工作区写入必须同时满足桌面沙箱、项目策略与单次任务授权。

## 四、任务执行记录

每项任务生成本地记录，至少包含：

- 随机任务 ID 与脱敏诊断编号。
- 会话 ID、项目根目录的本地引用、开始与结束时间、耗时和最终状态。
- 实际 provider、模型、本地／云端来源；没有证据时为“未知”。
- 权限档位、联网状态、是否调用工具、是否声明修改文件。
- 固定工作流的各阶段状态、耗时以及是否经过第二 provider 审核。
- provider 明确返回的输入、输出、缓存和推理 Token；缺失字段保持未知。
- 仅当存在带版本号的可信定价表且用户明确启用费用估算时计算费用。
- 脱敏后的错误分类与诊断编号，不保存令牌、授权码、邮箱或完整提示词。

任务记录先采用本地追加式存储，并设置数量和字节上限。面板只读取规范记录，不从聊天文本反向猜测执行者、Token 或文件改动。

## 五、界面

桌面设置新增“当前项目策略”，明确显示当前项目根目录、策略来源、权限上限、联网和工作区边界。保存前展示有效策略预览；扩大权限、允许联网或扩大写入目录需要明确确认。

会话侧新增“执行详情”入口，按时间线展示路由、provider 阶段、耗时、审核和错误。费用默认关闭。复制诊断时只复制脱敏编号和安全字段。

## 六、实施批次

1. I1：版本化项目策略 schema、校验、原子存储、损坏恢复与单元测试。
2. I2：设置 IPC 与项目策略界面；建立优先级解析和权限上限计算。
3. I3：将联网、provider、代理和读写目录边界接入下一任务的真实运行时。
4. J1：定义任务与阶段记录协议，把固定 Codex → Claude 工作流接入真实记录。
5. J2：接入可获得的 provider／模型／Token 证据和脱敏诊断编号。
6. J3：增加执行详情面板、保留策略和安装包级回归测试。

## 七、验收标准

- 未配置项目不改变现有全局行为；单次任务不能突破项目权限、联网和工作区边界。
- 损坏策略文件会保留原文件并回到“无项目覆盖”，不会启用宽松默认值。
- 项目策略不包含凭据，渲染器不能提交命令、模块路径或可执行文件路径。
- 禁止联网的项目不会调用云端 provider；指定 provider 失败时不会静默降级。
- 每个固定工作流阶段都有真实开始、结束、耗时和状态记录。
- 缺少 provider 证据的模型、Token、费用和文件改动显示“未知”。
- 诊断导出自动隐藏凭据、授权码、邮箱和提示词内容。
- 单元测试、桌面测试与实际安装包冒烟测试全部通过。

## 八、暂缓范围

Apple Developer ID 签名、公证、自动更新、公共插件市场和自动多轮修复仍不属于本批。费用估算在可信定价来源和用户开关完成前保持关闭。
