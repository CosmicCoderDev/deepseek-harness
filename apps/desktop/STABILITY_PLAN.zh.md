# DeepSeek Harness 桌面版稳定化计划

本文记录桌面版从“能够运行”提升到“普通用户能够稳定使用”的现状、缺口、实施顺序和验收标准。状态以 `feat/electron-desktop-rc8` 分支为准。

## 总体原则

- 先完善稳定性、可观测性和用户自助排错，再扩展新功能。
- 不把技术验证等同于正式产品能力；只有用户可发现、可操作、可诊断并通过测试的能力才标记为完成。
- Apple 签名与公证依赖 Apple Developer 资质，在资质取得前明确挂起，不阻塞代理管理和错误诊断。

## 本轮范围

### 4. 代理管理

桌面端增加可持久化代理设置，并提供以下模式：

1. **自动读取系统代理**：读取 macOS 当前系统代理；系统设置变化后自动刷新，不要求重启应用。
2. **手动代理**：用户填写 HTTP、HTTPS 或 SOCKS 代理地址，保存后立即应用。
3. **不使用代理**：清除桌面端注入的代理变量，provider 直接连接网络。

共同规则：

- `localhost`、`127.0.0.1`、`::1` 和 `.local` 地址始终绕过代理，确保 Ollama 等本地服务直连。
- 设置界面显示当前模式和实际生效地址。
- 提供 OpenAI、Anthropic、DeepSeek、Ollama 四项连通性测试；测试只检查服务可达性，不发送模型提示词，也不读取或显示令牌。
- 代理变化和测试结果写入脱敏诊断日志。

### 6. 错误诊断

错误展示采用“服务 + 阶段 + 可理解原因 + 建议操作”，至少覆盖：

- Codex 包装器未以 Node 模式启动。
- Codex 或 Claude Code 未登录、登录失效或授权超时。
- OpenAI、Anthropic、DeepSeek 网络不可达、代理不可达或请求超时。
- provider 可执行文件或打包依赖缺失。
- 未识别错误保留安全裁剪后的技术摘要，并指引用户复制诊断信息。

诊断导出与复制必须自动隐藏：

- API Key、Bearer Token、Authorization 和密码。
- OAuth 授权码、登录 URL 中的 `code`、`state`、`code_challenge` 等参数。
- 常见邮箱地址。
- 超长错误内容和可能包含凭据的环境变量；报告不得主动枚举进程环境。

## 第五优先级处理

Apple Developer 资质尚未申请成功，因此本轮不实施 Developer ID 签名、公证和依赖可信签名链的自动更新。现有未签名测试包继续用于内部测试，并在文档中明确 Gatekeeper 操作和风险。取得资质后另开发布质量阶段处理。

## 验收标准

- 普通用户无需终端即可查看、切换和测试代理。
- 自动模式能在系统代理变化后更新；Ollama 与其他本地端点不经过代理。
- Codex、Claude Code、OpenAI、Anthropic、DeepSeek 和 Ollama 的检测结果能区分成功、未配置、认证失败、代理失败和超时。
- 用户可一键复制脱敏诊断；导出文件和剪贴板内容不包含令牌、OAuth 授权码或邮箱。
- 新增逻辑具有单元测试，桌面构建和隔离打包冒烟测试通过。
